# wi-index

The disposable per-device SQLite index and search layer. `Index::open` places an FTS5 database in the platform cache directory, outside the vault; it syncs from files incrementally by stat and hash, answers text, title, permalink, metadata and bounded relation queries, and falls back to a labelled literal scan when it is missing or corrupt. The vault's ignore rules apply, `.obsidian/` and `.trash/` are never indexed, and a schema-version change rebuilds the index on open. Text and title queries are capped at `MAX_QUERY_BYTES` (2048 bytes) and `MAX_QUERY_TERMS` (64 terms); an over-cap query returns `Error::QueryTooLong` and never the literal fallback ([PROTOCOL](../../docs/PROTOCOL.md#read-limit-and-query-cap)). Design and query policy: [DESIGN](../../docs/DESIGN.md#index-and-search).
