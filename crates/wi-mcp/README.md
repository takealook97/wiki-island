# wi-mcp

The local MCP stdio server over `wi-store`: `wi mcp --vault <vault>` exposes 15 `wi_*` tools, the standing brief resource `wiki-island://brief` (pinned notes, current rules, then preferences as summaries, at most 2 KiB; also `wi brief`) and procedure resources, with no HTTP transport and no delete tool. `Engine::new(Vault, Arc<dyn Lifecycle>)` is the synchronous tool service and must stay on one thread; `Server::open` wraps it in a bounded asynchronous queue and flushes acknowledged records on shutdown. The `provider` module defines the lifecycle boundary: `VaultLifecycle` applies the engine and is used by `wi mcp`, `Unavailable` withholds lifecycle notes. A background thread registers the watcher, catches up the index and regenerates rules fragments after `initialize`; maintenance runs in the background service and `wi maintain`. Each tool result contains one compact JSON text block and no duplicate structured content. The JSON value is capped at 16 KiB: a plain note that does not fit whole is presented at a computed smaller tier (`presented`: omitted for `full`, otherwise `core`, `summary` or `title`) instead of being withheld; lifecycle claims and their qualifiers are delivered whole or withheld. A read aimed at a file is bounded by the vault's `max_note_bytes` and refused above it with `too-large`; listings still show such a file. Schemas, results, errors and the read limit: [PROTOCOL](../../docs/PROTOCOL.md).

`wi_work` with `action: "next"` always returns an item when open work exists. An oversized first item is reduced to its key, kind, path and a truncated reason. If mandatory identifiers cannot fit the requested byte target, the returned `max_bytes` reports the minimum effective budget; the complete data object fits that budget.

Missing hit `sources`, `status` and `claim_kind` mean null; missing `fallback` means false. The brief lists agent-noted rules and preferences separately under “Noted by your AI”, after protected items, within the same 2 KiB cap. Malformed frontmatter on creation returns `frontmatter-invalid` with a line and a repair hint. Existing vault notes remain readable; clients consume the result's JSON text block. Discovery omits repetitive descriptions and validation-only limits; runtime validation still enforces them.
