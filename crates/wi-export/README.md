# wi-export

Everything that leaves the vault for a host. It renders protected rules fragments and serves procedures as MCP resources, keeps a data-driven host table (`hosts`) with detection and diff-first MCP registration that preserves the original bytes, syncs procedures to host skill directories (`skills`), and manages the optional macOS launchd service that runs `wi watch` (`service`). It requires no daemon, network or model; all vault writes go through `wi-store`, and a host is configured only when its config already exists. Behavior: [INTEGRATIONS](../../docs/INTEGRATIONS.md), [SKILLS](../../docs/SKILLS.md), [OPERATIONS](../../docs/OPERATIONS.md#service).

Setup validates host settings and the service binary before changing connections. Host backups and ownership records stay under `.wiki-island/local/backups/`; uninstall restores unchanged host files byte for byte, removes files it created, and removes only empty containers recorded as created by the engine. User edits made after installation are retained while the owned registration is removed.

Skill directory names include a stable identifier digest. Existing owned names migrate once; foreign directories are preserved and a stable alternative is reported. Retiring a procedure removes its owned skill and marker while retaining extra user files. Only hosts with skill discovery receive exported directories; other hosts use MCP procedure resources. `WI_LAUNCHCTL` selects an alternative executable for service testing; the default remains `/bin/launchctl`.

Enabled skill targets use a persistent `.wiki-island/local/skills-digest` marker. CLI maintenance, the watcher hook and the MCP background loop compare current procedures with the last successful export; another process's maintenance cannot consume a pending update. A failed target stays pending. Codex registration uses standard TOML tables, including when converting an inline table. Service logs omit unchanged events and rotate at 1 MiB, retaining one previous log; uninstall removes both owned logs.
